The unified agreement keeps its identity from quotation through confirmation. Sales and purchasing use the same editor and agreement model. A customer-issued PO can be kept as supporting evidence on the sales record. A supplier PO is a local record of a purchasing commitment. Procurement can revise the quantities and values, retain earlier terms, or archive a purchase that falls through. Generated documents reflect the saved draft or selected sealed version. Signing or workflow state does not change the generated wording.

Trade Operations owns approvals and current commercial terms. Kingdee exchanges mapped table rows in the background and supplies fulfillment and accounting evidence. Linked orders can be revised and approved while sync is off or the source SO is closed. An independently amended SO remains visible as source evidence. It does not replace the locally approved terms.

**Ported** means there is a corresponding implementation. **Adapted** means the supported outcome uses a different workflow. **Partial** means an outcome or evidence is missing. **Source dependency** means a verified Kingdee mapping or account set is needed. The [manual probe matrix](0008-manual-probe-matrix.md) records runtime evidence separately.

## Document disposition

The source separates layout, projected facts and signed bytes. Trade Operations lets an operator select a named published layout on the shared draft. A recorded revision keeps that version of the layout and its artwork. Existing records can still resolve their legacy quotation and contract defaults. Upload the original `public/brand/epg/contract-chop.png` privately for use on sealed sales agreements. The separate `chop.png` belongs to shipping paperwork.

## Decision boundaries

- **Simpler UX** keeps one agreement, one place to revise the record, and one PDF preview/download. Preserve the reasons and evidence for any lifecycle operation that still requires action by Kingdee.
- **Adaptability** keeps the public template generic and gives operators versioned wording and rules. Exact tenant documents require explicit legal copy, layouts, fonts, source-field bindings and permitted brand assets.
- **Efficiency** reuses Bolt queues, conversion, imports, reports, permissions and history. An accounting-source invoice, receipt, refund or stock fact has one authoritative local projection.
- **Bolt already implements** account management, role-scoped reads, write checks, approval routing, auditing, notifications, credential storage and file access. Review their configuration and outcomes in the matrix.

### Remaining parity decisions

- **XLSX is accepted.** Orders headers and order lines, the price book and commission rules use a Bolt file sync with an explicit workbook schema, so the native Import, Export and Template actions read and write the same columns. Parties and warehouses publish export-only workbooks; products and the commission board download XLSX on demand. The order header workbook is matched by its unique sequential `number`; unchanged rows are skipped, so exporting, editing one draft and re-importing does not touch sealed orders. The line workbook is matched by order number plus the stable `line_key`, with blank keys inserting a generated key. Bulk import is one atomic file: every finding is collected before any row is written. Sales analysis and AR aging download the visible rows as on-demand XLSX workbooks; source facts, ledgers and generated statements remain export-only.
- **Approval request changes are a native state machine.** `Pending → ChangesRequested → Pending` is a resubmission of the same request by its requester; `Rejected` rolls the held write back to its checkpoint. A request holds its provisional write while ChangesRequested. When that write is a sealed confirmed agreement, the sales policy refuses a direct rewrite of the sealed terms, and a guarded automation cannot join the open request. The verified recovery is an approver Reject, which restores the draft, followed by a revised seal and a fresh request. Making Request changes itself release the draft requires either a rollback on the request-changes edge or an explicit withdraw/supersede action; both are platform decisions.
- **A2 source void, close and withdrawal stay in Kingdee.** They are guarded source lifecycle operations that need Kingdee's audit and void rules. Trade Operations archives reversibly, keeps source status as evidence and does not claim a source close or void it cannot prove. A direct SQL void/close would need a separate writer grant and native Kingdee validation.
- **A3 purchase facsimile is not a commitment.** A supplier purchase order is tracked as a local commitment with versions; it is not a signed customer contract. The customer PO upload, version filing and preview are implemented. Purchasing drafts default to the seeded Purchase contract layout, a tenant can select any other published layout, and a tenant supplies its exact clauses and artwork through that same pipeline; no data-model change is required.
- **A6 trade, origin, packaging, shipping, address and assignment fields are only added with a binding.** Each field needs a source column or a layout-defined print value, otherwise it duplicates the party, product, warehouse, owner or terms already on the record. The owner is the salesperson; logistics is a team and policy scope, not a per-line assignment. Customer delivery details and packaging can remain layout print fields until a tenant needs to filter or report on them, at which point the specific fields with verified source and document bindings are added.
