## Bounded batch C1 (completed after explicit ownership freeze)

**Problem:** general original-file qualification imports an offset-bearing instant predicate from the domain-specific wage receipt/correction module. The predicate itself has no wage, evidence, money, actor or database dependencies.

**Frozen candidate contract:** move the current implementation byte-for-byte to `iso-day.ts` as `isOffsetIsoInstant(value: unknown): value is string`; preserve source function grammar (real calendar day, hours 00–23, minutes/seconds 00–59, 1–9 optional fractional digits, Z or bounded signed offset, finite parsed instant). Keep UTC-only `isUtcIsoInstant` unchanged: it deliberately accepts UTC Z and at most three fractional digits, so these predicates are not aliases. `dateKey` resolves a business-zone day; `formatDateISO` returns a UTC day; neither can substitute for observation-zone conversion.

| Exact proposed write path | Change | Compatibility |
| --- | --- | --- |
| `src/lib/iso-day.ts` | Own pure offset-instant predicate copied from existing receipt helper | Additive export; existing calendar/UTC/dateKey behavior untouched |
| `src/lib/received-wage-components.ts` | Import canonical predicate for internal use; re-export it under existing `isReceiptSourceInstant` name | Every current consumer keeps the old named export; receipt/gross/refund shapes and original cash logic untouched |

The redundant annual asset regex accepts a superset of the existing source predicate; when source predicate succeeds, the regex and finite parse check already succeed. Remove only those two checks, not clock/zone comparisons or positive-size/approval checks. No model, custom-field, collection, seed, policy, payroll, leave, UI, platform or persisted snapshot writes belong to C1. One owner must hold all four files before execution. Existing import references below identify actual consumers; preserving the old export avoids a broad consumer rewrite. Targeted date/source validation belongs to later authorized verification, not this planning pass.

## Dynamic JSON source proof contract (read-only proposal; not implemented)

### Current actual path and gap

- `src/lib/datatypes/input_schema.ts` defines supported JSON Schema 2020-12 object/array/scalar nodes, recursive validation, closed object properties, an escaped RFC 6901 pointer and `InputJson`. Its actual `InputProof` is `{kind:REFERENCE|FILE|REFERENCE_AND_FILE,document?:string,bind_original_value?:boolean}` under `x-norbital.evidence`. Reuse these names; do not add a competing `bind_json` switch.
- The current `proofFault(path,value,demand):string|null` callback receives the original node. An absent callback refuses every requested proof. The array walker currently supplies paths such as `/children/0/date`; this is a position, not a stable source identity. No array stable-ID metadata or item-bound evidence adapter is present.
- `src/lib/declared-fact-evidence.ts:sourceEvidenceReady` is the exact existing scalar source adapter after C2: key and approval, declared reference/file demand, original received/expiry/document/valid-days, raw reference equality and `Object.is` original scalar equality. `ownedSourceEvidence` physically qualifies original file bytes/hash/field/approval/creation using the execution observation and timezone before synchronous checks. Retain these operations rather than building a second proof framework.
- Native `src/data/collection/fact_evidence/+collection.ts` derives scalar `attested_value` from the actual subject, refuses retrospective binding of an old unbound document and freezes original subject/key/ref/file/value/date metadata. `src/data/model/fact_evidence/+model.ts` already stores JSON `attested_value`; only the admitted scalar contract currently consumes it.
- Native owner reports the first dynamic entity path pins separate `input_schema_snapshot {snapshot_id,schema_kind:'entity_input_schema',schema_hash}` metadata on existing company/company_facts hosts. This is not a reserved property inside user JSON. Source evidence must identify that actual captured schema, not a caller boolean saying validation passed.
- Current `scalarFacts` in `src/lib/payroll/run/eligibility.ts` drops object/array values. `declared-facts.ts` callbacks and current entity/deferred resolution are scalar. Adding an editor or validator alone therefore does not carry nested original source values to actual calculations. The consumer owner must pair original JSON preservation and deferred source callbacks before activation.

### Proposed smallest metadata extension

On an array with original item-scoped proof, add `x-norbital.item_id_key:string`. This is a schema declaration naming a required nonblank string property of object items. The interpreter must reject the metadata on nonarrays/nonobject items, undeclared/nonstring/optional ID properties and arrays whose actual IDs are missing or duplicate. `uniqueItems` alone compares complete objects and does not establish identity. IDs are original immutable source IDs or native-assigned IDs for genuinely captured new items; never derive them from an index, amount, current label, hash of mutable values or an invented historical source. An old list lacking original stable IDs remains unavailable for item-bound proof until independently captured original source identity exists.

Keep the existing callback's first three arguments and propose an optional fourth address argument:

```ts
type InputProofAddress = {
 readonly schema_pointer: string;
 readonly item_identity: readonly {
  readonly array_schema_pointer: string;
  readonly id: string;
 }[];
};
proofFault(path: string, value: InputJson, demand: InputProof,
 address?: InputProofAddress): string | null;
```

`path` is the actual escaped RFC 6901 data pointer, including current indices, for operator errors and original capture. `schema_pointer` is the real pointer in the immutable schema, such as `/properties/children/items/properties/date`. Each repeated ancestor contributes one stable selector keyed by its real array schema pointer, such as `/properties/children`; nested arrays use their own schema pointer, including enclosing `items` segments. The interpreter derives the ID property from `item_id_key`; the input/evidence author cannot nominate a different `id_key`. Array reorder changes the diagnostic data path while preserving the schema pointer and original ID selectors. The callback must not certify an indexed array path without its complete stable selector chain.

Native and schema owners must agree these exact names before source freeze. This document records a concrete proposal, not a claim that current `InputSchema` admits these new keys.

### Additive original evidence addressing

Proposed optional fields on the existing evidence record, without renaming or dropping old fields:

| Field | Source and invariant |
| --- | --- |
| `fact_pointer` | Actual original data pointer captured by native admission; immutable. It records the original position but is never the repeated-item proof identity by itself |
| `input_schema_snapshot_id` | Actual subject's governing original captured schema snapshot ID; never caller-chosen unrelated schema |
| `input_schema_hash` | Exact captured schema hash; verify against host snapshot metadata |
| `schema_pointer` | Exact demanded node in that snapshot, derived by the schema walker |
| `item_identity` | Complete ordered ancestor selectors `{array_schema_pointer,id}`; derive from actual subject JSON and declared ID properties |
| existing `attested_value` | For new JSON-addressed evidence, native captures an envelope `{kind:"INPUT_JSON",value:InputJson}` when `bind_original_value` is demanded. The envelope distinguishes a captured JSON null from missing attestation. Existing scalar values keep their old representation; do not accept caller-only snapshots or backfill old unbound evidence |

For nonarray nested object paths, exact subject, captured schema and schema pointer identify the node; `item_identity` is empty. For repeated nodes, identity is subject + original schema + schema node + full original item selectors, not an ordinal. Admission proves the original pointer, selectors, node and demanded metadata agree. Runtime resolves the current/deferred selected original value by the IDs through the same schema, then requalifies actual original document and value at the selected source day. Missing/duplicate IDs, unresolved nodes, changed bound values, unrelated schema or malformed pointers refuse proof; they do not become defaults or zero.

Decode the native JSON attestation envelope only on the new schema-addressed evidence path; old scalar comparison does not decode it. This is source metadata around the captured JSON, not reserved properties inside the user value. Missing envelope remains unknown even when the candidate value is null.

Bind original JSON by exact recursive equality: object member order is irrelevant, array order remains significant for an explicitly whole-array snapshot, and JSON numbers must be finite. A leaf/item proof survives sibling array reorder through its stable selectors; do not silently sort a whole-array attestation or coerce date strings, numbers, nulls or missing keys. Keep old scalar `Object.is`, `bind_value`, `bind_scalar` and scalar key-only paths unchanged.

### Generic required-proof adapter and actual consumer pairing

Reuse `declared-fact-evidence.ts` for one schema-directed adapter rather than one helper per law. The async native/runtime loader still obtains physically qualified `fact_evidence` rows at actual observation and source timezone. A synchronous callback over those qualified rows checks:

1. Exact real subject collection/id and captured original schema identity/hash.
2. Exact schema node and stable selector chain, resolving the supplied original JSON without array-index substitution.
3. The declared `InputProof` reference/file/document demand using the existing evidence operations.
4. Original approval, ownership, positive safe bytes/hash, creation before actual observation, received/expiry/source-day validity and existing declared valid-days requirements. An original reference-only lawful alternative stays reference-only; no invented file demand.
5. Exact captured original JSON equality when `bind_original_value` is true; missing old attestation remains unknown. Clock/date predicates use the selected original source day and actual execution clock, not a later current-value substitute.

The required object/list property and per-item proof demand are interpreted from the schema. Any requested proof with no real qualified callback refuses, including frontend validation; a file upload or client-supplied "validated" flag is not a callback. Preserve the existing legacy-fact adapter for old required/conditional/document/valid-days/code/reference semantics. Do not flatten a nested pointer into a fake `FactKey` identifier or infer a statutory finding from arbitrary uploaded bytes.

Deferred scalar or nested changes must pass the selected original JSON and its subject/source snapshot into the callback at the actual effective day. Current JSON cannot certify a deferred historical value, and a bare accepted-key set cannot certify an entire nested tree. Original paid captures and evidence remain immutable; corrections require their actual original lineage.
