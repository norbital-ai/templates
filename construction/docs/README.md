## Developer Quickstart

Run all commands from the template root (`templates/construction`):

```bash
bun install --frozen-lockfile   # Install pinned Bolt & toolchain dependencies
bunx bolt check                 # Type-check, compile manifest, and verify migration history
bun run test                    # Run Vitest + @effect/vitest suites against PGlite
bunx bolt build                 # Build release bundle, generate next SQL migration if schema changed
```

### Schema Migrations & Seed Workflow

- **Schema changes:** Edit model declarations under `src/data/model/**` or custom fields under `src/data/custom_field/**`, then run `bunx bolt build` to generate the next sequential SQL migration under `migrations/` and verify full replay against a scratch database. Commit SQL files together with `migrations/snapshot.json`, `migrations/migrations.lock.json`, and `migrations/physical.json`. Never commit `.norbital/`.
- **Demo seeding:** `seed/+seeder.ts` defines the template's demo dataset binding for `bolt seed --bank=<path>` during environment reset or provisioning. A fresh workspace without seed data starts empty and ready to configure partners, item matrix rates, and connections.
- **Autodesk ACC secrets:** Configure `AUTODESK_CLIENT_ID` and `AUTODESK_CLIENT_SECRET` in the host's sealed secret store before pairing the `autodesk_acc` integration under **Settings → Integrations → Connections**.

## Core Architectural Highlights

1. **Single Federated BIM Model (`projects.bim_file`) & 1:1 `cost_estimates`:** Each project stores one `.ifc` model (`bim_file`, `bim_version`, `bim_costing_dirty`, `bim_summary`) and its browser takeoff (`bim_takeoff`, `bim_takeoff_views`), paired 1:1 (`unique: ['project_id']`) with `cost_estimates`. Replacing `bim_file` clears the takeoff, marks `bim_costing_dirty = true` and automatically transitions any non-void estimate to `void`. Non-BIM drawings, specifications, schedules, and handover records are filed in the hub's **Documents** tab (`project_files`).
2. **Tunneled 3-Step BIM Costing & Compliance:** Uploading or running Step 1 takes the model off in the browser (`src/services/viewer/takeoff.worker.ts` + `geometry-pass.ts`): it streams the `.ifc` in 4 MiB slices into unique archetypes, measures every element from its mesh, auto-cleans generic proxies/classes, deduplicates, and renders 4-angle pictures. Inside **BIM → BIM Costing**, the tunneled 3-step **BIM process** guides teams through **Step 1 (`Parse & Analyze`, `phase: 'prepare'`)** — populating proposed cleaned BIM mappings (`asset_mappings`), proposing missing `item_matrix` entries via System 2 (held for commercial approval), and running BCA/CORENET X/company SOP compliance lints (`projects.bim_compliance`) — **Step 2 (`Review Proposals & Lints`)** — inline review/approval of Item Matrix rates, Clean BIM edits, 3D lint inspection, and cleaned `.ifc` download — and **Step 3 (`Generate Cost Estimate`, `phase: 'cost'`)** — generating the 1:1 BOQ costing matrix (`cost_estimates`) rendered under a compact KPI header with debounced auto-save inline editing in a bounded internal-scroll table. The server never parses IFC.
3. **Client-Side 3D Viewer & Two-Tier `.frag` Cache:** `src/services/viewer/IfcViewer.svelte` (backed by `engine.ts`) boots Three.js + `@thatopen/components` in parallel with a two-tier fragment cache (in-memory LRU-4 + persistent browser `CacheStorage` `norbital-ifc-fragments-v2`), converting raw IFC files once inside a disposable `web-ifc` WASM Web Worker. Includes Orbit / Pan / Inspect modes, proportional wheel and trackpad-pinch zoom, keyboard navigation, `Iso`/`Top`/`Front`/`Side` presets, X/Y/Z section planes, an **Asset visibility** panel (hide/isolate selected elements, toggle IFC categories, unhide/show all), and isolation of a selected BIM task's or the 4D slice's elements (brand colour, rest translucent).
4. **Catalog-Wired Commercial Ledger & Standalone Ad-hoc Costs:** Every line item on client contracts, subcontracts, Variation Orders (`contracts`), and Purchase Orders / Delivery Orders / Invoices / Claims (`commercial_documents`) must reference a valid `item_matrix` code (or project BIM takeoff bucket) via `resolveCatalogLines` — zero free-text money lines. Non-BIM site costs live in standalone `adhoc_costs` with a mandatory `catalog_item_id` (`on_delete: 'restrict'`). Everything reconciles per catalog code in **Finance → Cashflow & Budget** (`computeCatalogCashflowBreakdown`) using exact Effect `BigDecimal` math.
5. **Simplified Programme & Tasks + Multi-Channel AI Intake:** All project progression is tracked via **Programme & Tasks** (4D timeline nested by `wbs_path`, table, and board behind an icon-only view toggle, backed by Primavera P6 `.xer`, MS Project `.xml`, XLSX/CSV, and two-way Autodesk ACC sync). Each task (`bim` or `adhoc`) uses a borderless Linear-style Markdown `description` (floating bubble & `/` slash menus, `images: 'attachments'`) and a dedicated **Activity** tab backed by polymorphic `activities` (`title`, plain-text `description`, `occurred_at`, optional `attachments`). WhatsApp and email messages are mirrored into `project_messages` as they arrive (`sync_messages`) and scheduled into `file_project_messages`, which runs a 30-message windowed System 1 classifier and batches useful project messages into one System Agent (`ctx.ai.sys_2.task`, with `ctx.ai.sys_2.infer` fallback) to file tasks, activities, variations, and commercial documents.
