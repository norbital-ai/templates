# HR 与薪资

本工作区根据雇佣条款、排班、考勤、已审批业务记录和生效规则计算薪资。每张工资单保留来源记录和计算依据。

**当前合规验证尚未完成。** 法定计算、离职结算和外部申报仍有待解决事项，详见[合规矩阵](docs/compliance-matrix.md)。测试通过不代表已验证全部适用法律。

## 应用

| 区域         | 用途                                         |
| ------------ | -------------------------------------------- |
| 员工自助服务 | 查看雇佣信息、记录事项、申请休假和查看工资单 |
| 法律实体     | 维护实体、薪资设置和已发布假日               |
| 人员         | 维护档案、合同、生效条款、法定事实和离职记录 |
| 事项         | 审核考勤、休假、报销、一次性付款和贷款       |
| 薪资         | 创建常规期间、审核工资单、记录付款和导出报表 |
| 设置         | 查看生效规则、编辑草稿目录和比较版本         |
| 考勤机       | 记录考勤和管理人脸登记                       |

访问和审批策略区分员工、主管、人事控制员、人事经理、高级管理层与考勤机。自动化仍须遵循审批要求。

## 薪资输入

| 业务类型     | 来源                                           | 结果                           |
| ------------ | ---------------------------------------------- | ------------------------------ |
| Work         | 生效条款、班次模式、排班、考勤和实体已发布假日 | 工资、加班、夜班津贴和缺勤扣款 |
| Leave        | 生效休假规则和已审批休假记录                   | 带薪或无薪缺勤、兑现和冲销     |
| Claim        | 已审批费用申请                                 | 报销和追回款项                 |
| Allowance    | 雇佣条款中的月度金额                           | 随工资分摊的经常性收入或扣款   |
| Ad hoc       | 一次性付款目录下的已审批申请                   | 奖金、补薪、离职付款和追回款项 |
| Loan         | 贷款协议和还款计划                             | 净薪限制内可回收的整期还款     |
| Contribution | 生效法定规则、员工事实和计算所得薪资项目       | 员工扣款、雇主缴款和税款       |

每个法律实体每个期间只允许一次常规薪资运行。草稿可删除后重建，已付款结果受保护。迟批记录仍归属于原合同。常规期间模型本身不保证满足离职付款期限，也不提供税务清算扣留流程。

同一员工可在不同实体任职；同一员工在同一实体的合同日期不得重叠。再入职建立新合同，但依法应合并的年度法定累计不得清零。

设置和目录具有生效日期，封存后不可修改。假日由各实体独立维护，发布后才用于薪资计算；已有薪资保留计算时捕获的假日依据。

## 自动化

| 自动化                     | 触发方式              | 结果和复核要求                                                                                                         |
| -------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `statutory_drift`          | 每月或按需            | 对比官方来源中的缴款规则和休假额度。仅对支持的变更及已知法定生效日期创建未封存草稿。证据不足或不支持的变更须人工复核。 |
| `leave_encashment_on_exit` | 合同更新或按需        | 为标记为离职兑现的休假余额和符合条件的离职付款提交审批。解雇原因本身不构成没收依据；重试跳过已有申请。                 |
| `leave_encashment_due`     | 每日 01:00 UTC 或按需 | 处理提前登记的离职。未来离职不预留休假余额；到期后按运行时计算的余额提交审批。                                         |
| `holiday_import`           | 每年 10 月 1 日或按需 | 从实体的 Google Calendar 来源导入候选假日，由人事复核并发布。                                                          |

漂移检测不覆盖全部法定字段。离职审批须确认权益、计价、任何合法没收依据及付款时间。详见[自动化验收要求](docs/compliance-matrix.md#automation-acceptance)。

## 验证

在本模板目录运行：

```bash
pnpm lint
pnpm sync
pnpm test
pnpm test:e2e
```

`sync` 生成工作区类型及 `.norbital/artifact/` 中的可移植构件。测试使用虚构夹具和隔离的本地主机；浏览器测试默认无界面运行。漂移集成测试替换了研究模型和官方网页读取器，不能证明在线服务可用或部署成功。

模型、集合校验、表单和导入导出位于 `src/collections/`，应用位于 `src/apps/`，自动化位于 `src/automations/`，中英文文案位于 `src/i18n/`。`src/+agents.md` 提供代理上下文，不授予权限。

本地编辑仅影响源码和本地构件。现有租户继续使用其记录的发布版本，直到正常发布与配置流程应用变更。
